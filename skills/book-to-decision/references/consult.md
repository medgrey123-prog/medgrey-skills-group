# 调用知识库，准备决策

## 1. 建立当前情境

把用户陈述拆成已知事实、解释、目标/价值取舍、约束与未知项。沿用已给信息。缺失条件影响候选适用性时，提出最有区分力的问题；可以先给条件分支，不强制完整问卷。

## 2. 检索并读取

定位用户指定知识库，读取 INDEX 和相关子索引，以问题、症状、目标、同义词、约束搜索。读取命中单元全文及它们的冲突、替代、前置关系；不凭索引摘要定案。

无匹配时换同义词和上位问题再查；依然无匹配则说明知识库未覆盖。无法访问整个库时报告实际读取范围，不声称已检查所有候选。向量搜索是可选优化，不能代替条件检查。

## 3. 条件筛选

每个候选分别标记：
- 可考虑：已知事实满足关键前提，尚未发现排除条件。
- 条件待确认：关键前提未知，列出需确认内容。
- 不适用：已知条件触发排除项，写明原因。

语义相似不等于适用。Agent 推断的前提保持推断标签。不能把未知当作满足，也不能把缺证据直接当作反证。

## 4. 比较及准备材料

只比较真实存在且相关的方法，不为满足固定条数凑方案。按目标匹配、条件、证据局限、成本、风险、失效信号比较。多个来源冲突时保留分歧与原因；可以给有条件的倾向，不替用户最终选择或执行。

默认输出：
1. 当前情境与决定性未知项。
2. 候选方法表：方案/单元 ID、适用状态、理由、成本风险、证据局限。
3. 已排除的方法及触发的排除条件。
4. 重要冲突、什么新信息会改变判断。
5. 可进行的低成本验证及观察指标（补充建议明确归属）。
6. 需要人判断的取舍与下一步决定。

知识库只有一个可用方法时如实说明。知识库以外的常识或新建议必须标注「库外建议」，不得伪装成书中观点。

## 5. 使用反馈

用户提供结果后，可以记录日期、原情境、采用方法、实际结果与限制；经明确要求再更新知识库。单个成功案例不升级为普适证据，单个失败也不直接删除原主张。不要隐式记忆未经保存的结果。
