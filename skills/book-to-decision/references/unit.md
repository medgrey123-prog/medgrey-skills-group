# 最小知识单元与知识库约定

版本：1.0。存储使用 Markdown，便于文本搜索和人工维护；无需数据库或嵌入模型。内容量决定单元数，不设条数配额。

## 目录

- `INDEX.md`：检索入口。逐行列单元 ID、标题、问题/情境、触发词及同义词、关键排除条件、相对文件路径。大库按问题域拆子索引，入口记录所有分片。
- `units/<稳定ID>.md`：独立知识单元。
- `CONCEPTS.md`：有调用价值的概念、作者定义、易混淆概念与相关单元；无内容时省略。
- `SOURCES.md`：来源清单，作者/版本已知项与覆盖范围；不保存不必要的私人文件路径。
- `CONFLICTS.md`：有实质冲突时创建，记录双方 ID、命题、情境/目标/证据差异及待判断事项。
- `PROGRESS.md`：逐章节或文本分段记录已读/已处理/待处理、对应单元、遗漏与合并理由、下一步位置。提供恢复入口。

新 ID 采用可读且不重用的形式，例如 `communication-001`。更新同一命题保留 ID；新命题新建 ID；删除或合并留下替代指向。不得覆盖不相关文件。

## 每个单元的字段

可直接用以下标题写 Markdown。没有信息的字段明确写「来源未提供」「待确认」或「不适用：理由」。推断附在对应字段并标明，不要只在全文结尾统一免责声明。

| 字段 | 保存什么 |
|---|---|
| ID / 标题 / 版本 | 稳定标识；标题描述具体问题或行动 |
| 情境与问题 | 可观察到的状态、主体、待解决问题、预期目标 |
| 触发词 | 常见用户问法、症状、同义词；不要只写作者术语 |
| 核心主张与性质 | 主张；区分事实陈述、解释、价值判断、建议 |
| 概念 / 原则 / 立场 | 必要定义、约束、作者偏好；引用词典可避免重复 |
| 判断条件 | 适用前提、排除条件、仍需收集的信息 |
| 候选方法 | 方法是什么，适用目标；可引用其他单元作替代 |
| 操作 | 输入、顺序、每步动作与可观察产出；仅有理论则标「非直接操作单元」 |
| 因果解释 | 作者为何认为方法有效；推断与原文区分 |
| 证据 | 来源提供的研究/观察/经验/案例/断言，以及局限；证据不足不等于已证伪 |
| 成本与风险 | 所需资源、机会成本、可能副作用 |
| 失效与反例 | 不成立的情境、失败信号、何时停止或改用别法 |
| 结果检查 | 观察什么判断是否有效；作者无指标则允许标注的建议指标，不杜撰数字门槛 |
| 关系 | 支持/前置/替代/冲突/相似单元 ID；无关系则写无 |
| 来源与内容归属 | 书名或文件名、章节若有；哪些来自作者、哪些为 Agent 补充 |

## 保留与舍弃

保留会改变识别情境、选择方法、执行或判断边界的信息。案例如果提供边界、失败机制、反例或可迁移操作，保留关键条件和结果；只起装饰、重复说服作用的故事可压缩或略去，在覆盖记录中写理由。独特概念或原则即使没有步骤也可以保留；不必硬改成 SOP。

## 质量判断

用一个匹配情境、一个不匹配情境、一个条件未知情境检查主要单元；输入应自然，不直接给作者术语。检查能否分别调用、排除、暂缓判断。检查的是知识表达可用性，不代表书中方法已在现实验证。
